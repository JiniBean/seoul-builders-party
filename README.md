# 서울 빌더즈 파티

**내 캐릭터 파일 하나를 PR로 보내고, 발표자가 검토하면 함께 완성되는 파티.**

기능 목록보다 “Agent에게 기존 저장소의 변경을 요청하고, 다른 사람이 검토한다”는 과정을 직관적으로 보여주는 워크숍 작품입니다. 참가자는 Replit Agent에서 캐릭터 JSON을 추가하고, 웹 파티장은 결과를 확인하는 용도로 씁니다.

## 구분해서 사용하세요

- 파티 명단: 저장소의 `src/participants/*.json`에서 읽습니다. 파티 주인장 별빛(`starlight.json`)이 처음부터 방에 있고, 예시 친구 5명은 "예시 친구 부르기" 버튼을 눌렀을 때만 들어옵니다. 모두 가상의 캐릭터입니다.
- Agent로 참가: 요청문을 복사해 저장소를 연 Replit Agent 대화창에 붙여 넣습니다. 웹에서 캐릭터를 직접 편집하거나 등록하지 않습니다. 자신의 Preview와 병합 후 원본 파티는 구분합니다.
- 리허설: 이 브라우저에서만 제안·피드백·수정·합류를 연습합니다. GitHub API를 사용하지 않습니다.
- 실전: 원본 저장소 https://github.com/TheReplitLab/seoul-builders-party 를 Fork해 Repos·PR·리뷰·병합을 실제로 수행합니다. 참가자 Fork → 원본 대상 PR 경로는 아직 리허설로 검증하지 않았습니다.

## 독립 저장소에서 실행

저장소 루트에서 Node.js 22 이상:

```sh
npm install
npm run dev
```

외부 서비스, DB, API 키는 필요하지 않습니다. Vite는 `PORT`를 따르며 기본 5173번 포트를 사용합니다.

```sh
npm test
npm run build
```

이 저장소에는 단독 package.json과 Vite 설정이 들어 있습니다. API 서버나 다른 폴더는 필요하지 않습니다.

## 발표자가 준비할 것

1. 이 저장소가 발표자의 공개 원본입니다. 참가자는 Fork해서 PR을 보냅니다.
2. `.github/workflows/checks.yml`의 구조 검사·빌드가 동작하는지 확인합니다.
3. main에 필수 리뷰·검사 규칙을 적용할 수 있는지 계정 정책을 확인합니다. AGENTS.md는 권한 통제가 아닙니다.
4. 대표 참가자 2~3명과 Fork·Repos 연결·원본 대상 PR을 사전 검증합니다.
5. 발표자용 원본 main 실행 환경을 별도로 유지합니다. 참가자 샌드박스와 혼동하지 않습니다.
6. PR 검토 때 변경 파일이 참가자 JSON 한 개뿐인지, 실제 검사 결과와 개인정보를 확인합니다.
7. 한 번 수정 요청을 하고 재수정 결과를 확인한 뒤 승인·병합합니다.

## 병합 직후 화면 반영

**PR 생성 ≠ 승인 ≠ 병합 ≠ 배포**입니다. 이 프로젝트는 GitHub 자동 배포를 설정하지 않습니다.

개발 서버에서 보여 줄 경우, 작업 중인 변경이 없는 **발표자 원본 main 복제본**에서:

```sh
git status
git pull --ff-only origin main
```

main 브랜치인지와 깨끗한 작업 상태를 먼저 확인하세요. 충돌·다른 변경이 있으면 멈추고 해결합니다.
Vite 개발 서버가 파일 추가를 반영한 뒤 페이지를 새로고침합니다. 반영이 안 되면 서버를 재시작합니다.
정적 호스팅을 사용하면 `npm run build` 후 해당 호스트의 정식 배포 절차가 별도로 필요합니다.
동기화·배포를 설정하거나 확인하기 전에는 “병합 즉시 모든 화면에 자동 등장”한다고 말하지 않습니다.

## 10분 현장 시연

- 0~1분: 기존 파티와 내 캐릭터를 보여 줍니다.
- 1~3분: 참가자가 새 JSON 파일 한 개를 만들어 자신의 실행 화면에서 확인합니다.
- 3~5분: 실제 PR의 Files changed·검사 결과를 검토합니다.
- 5~7분: 한마디를 더 구체적으로 써 달라는 피드백 후 같은 PR을 업데이트합니다.
- 7~9분: 승인·병합, 발표자 main 최신화·화면 갱신으로 합류를 확인합니다.
- 9~10분: Repos·GitHub·발표자의 역할을 정리합니다.

온라인 시연이 실패하면 명확히 표시된 로컬 리허설을 사용하거나 사전 녹화를 보여 주세요. 실제 PR인 것처럼 설명하지 않습니다.
