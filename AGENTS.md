# Seoul Builders Party workshop

- Read README.md and CONTRIBUTING.md first.
- A participant contribution adds ONE new `src/participants/<id>.json` file.
- Use a nickname, not a legal name, email, phone, personal URL, or sensitive information.
- Follow the schema and character limits in existing JSON files and `src/lib/party.ts`.
- Do not edit another member, dependencies, shared UI, scripts, deployment settings, or GitHub workflows for a character contribution.
- Run `npm test` and `npm run build`; record passed, failed, and unverified checks honestly.
- Check the actual character preview and mobile layout if browser access is available.
- A local rehearsal is NOT a GitHub PR, independent review, or shared roster update.
- Branch, commit and open a draft PR only when requested. Confirm the original upstream repository as the PR target if working from a fork.
- Do not merge, publish or change repository rules. Only the authorized host reviews and decides.
- A PR, approval, merge and deployment are separate events. No automatic hosting deployment is configured.
- These rules are contribution guidance, not access-control enforcement.
